# 婴儿车选购评分器

一个给新手父母用的**婴儿车选购评分与多产品对比工具**。录入多款婴儿车的参数，按预设的 **100 分评分体系**自动打分，并给出排名、标签、风险提醒、横向对比和两两 PK 结论。

- 纯 HTML + CSS + 原生 JavaScript，**零依赖、零框架、零构建**
- **不需要后端、不需要数据库、不需要启动服务器**，双击 `index.html` 即可使用
- 数据保存在浏览器本地 `localStorage`，不上传任何服务器
- PC / 平板 / 手机全适配，375px 宽度手机可正常使用

---

## 一、如何运行

### 方式 1：直接双击（推荐）

```text
双击 index.html
```

用 Chrome / Edge / Safari 打开即可，无需 npm、无需构建。

### 方式 2：单文件版

如果只想发一个文件给别人：

```text
双击 index.standalone.html
```

这是把 CSS 和 JS 全部内联后的独立版本，功能与主版本完全一致。

> 单文件版由 `node build-standalone.js` 生成。**日常使用不需要执行它**，只有在你改了 `css/style.css` 或 `js/app.js` 并希望同步更新单文件版时才需要跑一次。

### 方式 3：本地静态服务器（可选）

某些浏览器（尤其是 Safari）对 `file://` 协议下的 `localStorage` 限制较严。如果发现刷新后数据没保存，改用本地服务器打开即可：

```bash
python -m http.server 8080
# 然后访问 http://localhost:8080
```

## 三、功能说明

### 多产品管理

新增、编辑、复制、重命名、删除、清空全部。新增时自动命名为 `婴儿车 1`、`婴儿车 2`……之后可自行修改品牌和型号。支持同时比较 10 款以上产品。

### 实时评分

修改任意参数后，编辑弹窗顶部的总分、等级、星级、完整度、每分成本会立即刷新，同时列表卡片、排名、对比表、PK 结论全部同步更新。

### 综合排名

顶部显示排名（前三名带奖牌）。支持按 **综合得分 / 价格 / 重量 / 每分成本 / 新生儿适用 / 避震 / 轻便程度** 排序。缺失数据的产品自动排在最后。

### 产品类型标签

根据各维度得分自动打标签，一款车可同时有多个标签：

`轻便型`、`旅行型`、`舒适型`、`全地形型`、`均衡型`、`新生儿友好`

### 风险提醒（不只看总分）

| 触发条件 | 提醒 |
| --- | --- |
| 产品标 6 月+，且你勾选了「新生儿出生就开始用」 | ⚠ 不建议作为新生儿主力婴儿车使用 |
| 执行标准得分 ≤ 2 | ⚠ 国内安全认证信息不足，建议购买前确认 CCC 认证和执行标准 |
| 执行标准得分 = 0 | ⛔ 安全认证 / 执行标准信息严重不足 |
| 整车重量 > 11kg | ⚠ 整车较重，经常搬上搬下或放后备箱可能不方便 |
| 避震得分 ≤ 4 | ⚠ 更适合商场、柏油路等平整路面 |
| 未填写重量 | ⚠ 缺少重量信息，车重项按 0 分计算 |
| 信息完整度 < 80% | 信息完整度：xx% —— 建议补充后再比较 |

### 横向对比表

总分、价格、重量、每分成本、13 个维度、完整度、场景匹配度逐行对比。**每行最高分绿色高亮、最低分橙红提醒，并列时同时高亮**；全行数值相同时不高亮。手机端可横向滚动，首列固定。

### PK 对比

选择产品 A 和产品 B，自动列出各自优势（带具体数值，如 `更轻：5.9kg vs 10.4kg`、`折叠体积更小：56.7 L vs 189 L`），并用**确定性规则**（不调用 AI）生成结论：

```text
如果你经常开车、上下楼、坐高铁飞机：更推荐 A（便携组 30/30）
如果你更在意新生儿舒适性和烂路避震：更推荐 B（舒适通过组 38/38）
综合评分更高：A（100 分 vs 86 分）
如果预算优先：A 的每分成本更低（¥33.00/分）
```

若一方存在一票否决级风险，该提示会被顶到结论最前面。

### 使用场景偏好 —— 客观分与个人匹配度分开

勾选「新生儿出生就开始用 / 经常开车 / 经常上下楼 / 经常坐高铁飞机 / 主要逛商场 / 经常走公园石板路 / 特别看重避震 / 特别看重轻便 / 特别看重收车 / 希望一辆车用到 3～4 岁」。

**这些偏好不会改变 100 分客观评分**，只会额外生成一个「与你的使用场景匹配度」百分比：

```text
综合评分：88 / 100
与你的使用场景匹配度：92%
```

匹配度算法：把所勾选场景的维度权重累加，按 `Σ(权重 × 该维度得分率) / Σ权重` 计算。若产品要求 6 月+ 而你选择了从出生开始使用，匹配度会额外下调 40%。

### 价格与每分成本

```text
每分成本 = 售价 ÷ 总分
```

例如 `3299 ÷ 88 = ¥37.49 / 分`。**这只是辅助信息，价格低不等于产品更好**，页面中也做了同样提示。

## 四、100 分评分体系

总分严格等于 **100 分**，共 **13 项**。程序启动时会校验合计值，若不等于 100 会在控制台告警。

| # | 项目 | 满分 | 输入方式 |
| --- | --- | --- | --- |
| 1 | 新生儿适用性 | 18 | 下拉选择（核心安全项） |
| 2 | 执行标准 / CCC | 8 | 下拉选择（A～G 七档） |
| 3 | 安全配置 | 12 | 勾选 4 项 |
| 4 | 车重 | 12 | 输入 kg，自动换算 |
| 5 | 避震能力 | 12 | 下拉选择 |
| 6 | 收车便利性 | 10 | 下拉选择 |
| 7 | 折叠体积 | 8 | 档位下拉 + 可选长宽高 |
| 8 | 双向功能 | 6 | 下拉选择 |
| 9 | 座舱舒适性 | 6 | 勾选 4 项 |
| 10 | 遮阳篷 | 4 | 下拉选择 |
| 11 | 轮子与操控 | 2 | 下拉选择 |
| 12 | 储物能力 | 1 | 勾选 |
| 13 | 做工 / 售后 | 1 | 勾选 |
| | **合计** | **100** | |

<details>
<summary>各项明细档位</summary>

**1. 新生儿适用性（18）**：官方 0 月+ 且完全/接近平躺或独立睡篮 = 18；官方 0 月+ 但躺姿或支撑一般 = 14；官方要求 6 月+ = 6；月龄不明确 = 0

**2. 执行标准 / CCC（8）**：A 可查 CCC + 符合当前国内标准 + 有新版标准检测依据 = 8；B 可查 CCC + GB 14748-2006 = 7；C 可查 CCC 但未标执行标准 = 5；D 标 GB 14748-2006 但 CCC 无法确认 = 3；E 仅 EN 1888 / ASTM = 2；F 仅企业标准 Q/XXX = 1；G 无信息 = 0

**3. 安全配置（12）**：五点式安全带 +4；一脚双刹/联动刹车 +3；车架折叠锁定可靠 +3；安全带高度可调/防误操作 +2

**4. 车重（12）**：≤6.5kg = 12；>6.5～8 = 11；>8～9 = 9；>9～11 = 7；>11～13 = 4；>13 = 2；未填写 = 0（并提示「缺少重量信息」）

**5. 避震能力（12）**：大轮+四轮有效避震 = 12；中等轮径+四轮避震 = 10；后轮避震 = 7；小轮+基础避震 = 4；基本无避震 = 2；不明确 = 0

**6. 收车便利性（10）**：单手一键收车+收车后可站立 = 10；一键收车 = 8；两步收车 = 6；操作复杂 = 3；不明确 = 0

**7. 折叠体积（8）**：非常紧凑/旅行车级别 = 8；普通轿车后备箱轻松放下 = 7；比较占空间 = 4；折叠后仍非常大 = 2；不明确 = 0。填写长宽高后额外显示 `59 × 49 × 29 cm` 与换算体积（升），尺寸只用于展示，不影响得分

**8. 双向功能（6）**：座椅真正正反双向 = 6；睡篮/提篮阶段可面向父母 = 4；只能正向 = 2；不明确 = 0

**9. 座舱舒适性（6）**：靠背高度充足 +2；座宽充足 +2；腿托可调 +1；透气设计好 +1

**10. 遮阳篷（4）**：UPF50+ + 大遮阳篷 + 延长篷 + 透气观察窗 = 4；UPF50+ + 大遮阳篷 = 3；普通 = 2；较差 = 1；不明确 = 0

**11. 轮子与操控（2）**：转向顺畅/前轮万向锁定/过坎好 = 2；普通 = 1；不好推或不明确 = 0

**12. 储物能力（1）**：置物篮较大、开口方便 = 1，否则 0

**13. 做工 / 售后（1）**：品牌售后完善、配件容易购买 = 1，否则 0

### 评分等级与星级

| 总分 | 等级 |
| --- | --- |
| 90～100 | 非常优秀 |
| 85～89 | 很推荐 |
| 80～84 | 值得买 |
| 75～79 | 可以购买，但存在明显取舍 |
| 70～74 | 除非价格特别合适 |
| < 70 | 不太推荐 |

星级 = `总分 / 100 × 5 颗星`，用 CSS 按比例填充实心星，因此**与总分严格同步**，不会出现「分数变了星级不变」的情况。

## 五、如何修改评分规则

**所有评分逻辑集中在 `js/app.js` 顶部的配置区，UI、评分、对比表、规则说明会自动跟随，无需改动渲染代码。**

评分逻辑本身在 `calculateScore(product)` 中，是不接触 DOM 的纯函数。

### 改某一档的分数

找到 `DIMENSIONS` 中对应维度，改 `score` 即可：

```javascript
{
  key: 'suspension', field: 'suspension', label: '避震能力', short: '避震',
  max: 12, type: 'select',
  options: [
    { value: 'bigFour', label: '大轮 + 四轮有效避震', score: 12 },  // ← 改这里
    ...
  ]
}
```

### 增加 / 删除一个档位

在该维度的 `options` 数组里增删一项即可。下拉框、规则说明表格都会自动更新。

> 若删除的档位在已保存的数据里出现过，导入/读取时会被自动归为「不明确」，不会报错。

### 改车重换算表

```javascript
brackets: [
  { maxKg: 6.5, score: 12, label: '≤ 6.5kg' },   // 按 maxKg 从小到大排列
  { maxKg: 8,   score: 11, label: '>6.5 ～ 8kg' },
  ...
]
```

### 改勾选项分值

```javascript
items: [
  { key: 'fivePointHarness', label: '五点式安全带', score: 4 },   // ← 改这里
  ...
]
```

### 新增一个评分维度

在 `DIMENSIONS` 中追加一项（`type` 可选 `select` / `checks` / `weight` / `volume` / `bool`），并在 `emptyProduct()` 里补上对应默认字段。表单、评分、对比表、规则说明会自动生成。

> **注意：13 项 `max` 之和必须仍为 100。** 程序启动时会校验，不等于 100 会在浏览器控制台打印告警。

### 改等级 / 标签 / 场景权重

- 等级：`GRADES`
- 产品类型标签：`TAG_RULES`
- 使用场景与维度权重：`SCENARIOS`
- 排序方式：`SORT_OPTIONS`
- 卡片上用进度条展示哪几个维度：`CARD_BAR_KEYS`

## 六、如何修改执行标准

标准信息**集中定义在一个配置对象里，没有散落在 UI 代码中**：

```javascript
// js/app.js
var STANDARD_CONFIG = {
  asOf: '2026 年 8 月',
  currentStandard: 'GB 14748-2006',
  nextStandard: 'GB/T 14748-2025',
  generalSafetyStandard: 'GB 46516-2025',
  nextEffectiveDate: '2026-11-01'
};
```

修改这个对象后，以下位置会自动更新：

- 「评分规则说明」区域的标准提示文案（由 `standardNotes()` 生成）
- 执行标准维度中 B、D 两个选项的文案

截至 2026 年 8 月的现状：

- `GB 14748-2006` 仍属于现行儿童推车标准
- `GB/T 14748-2025` 将于 `2026-11-01` 实施
- `GB 46516-2025` 将于 `2026-11-01` 实施

标准换代后，只需把 `currentStandard` 改成新标准、更新 `nextStandard` 与 `nextEffectiveDate`，必要时调整 `DIMENSIONS` 中 `standard` 维度的选项文案与分值。

## 七、localStorage 说明

- **Key**：`baby_stroller_scorer_data`
- **自动保存**：任何改动（新增/编辑/删除/复制/场景勾选/导入/清空）都会自动写入，**不需要手动点保存**
- **写入节流**：改动后 150ms 内合并写入一次，连续输入不会造成卡顿
- **容错**：若浏览器禁用了 localStorage 或空间已满，会弹出 Toast 提示，页面不会崩溃

### 数据结构（含版本号）

```javascript
{
  version: 1,
  preferences: {
    scenarios: ["newbornFromBirth", "car"]
  },
  products: [
    {
      id: "uuid",
      brand: "Cybex",
      model: "Melio Carbon",
      price: 3299,
      newborn: "flat",
      standard: "B",
      safety: {
        fivePointHarness: true, linkedBrake: true,
        frameLock: true, adjustableHarness: false
      },
      weightKg: 5.9,
      suspension: "smallBasic",
      folding: "oneHand",
      foldedGrade: "car",
      foldedSize: { length: 74, width: 51, height: 21 },
      reversible: "forward",
      comfort: {
        tallBackrest: true, wideSeat: false,
        adjustableLegRest: false, breathable: true
      },
      canopy: "upfBig",
      handling: "good",
      storage: true,
      aftersales: true,

```

### 版本迁移

`migrateData(raw)` 负责把任意版本 / 任意来源的数据转换成当前版本结构：

- 无 `version` 字段的旧数据、甚至一个裸的产品数组，都能被正确读取
- 每个产品都会经过 `normalizeProduct()` 重建：非法字段丢弃、类型强制转换、枚举值校验、负数拒绝
- 重复或缺失的 `id` 自动重新生成

未来结构升级时，在 `migrateData` 中按 `version` 加分支即可。

## 八、导入 / 导出说明

### 导出

点击顶部「导出」，下载：

```text
baby-stroller-data.json
```

内容包含 `version`、`exportedAt`、`preferences`、`products`。

### 导入

点击顶部「导入」选择 JSON 文件。

- **导入前一定会提示**：当前已有数据时，会弹窗让你选择「覆盖现有数据」「追加合并」或「取消」；追加时导入产品会重新分配 id，不会覆盖同名产品
- **严格校验**：格式错误、根节点不是对象/数组、缺少 `products`、`products` 为空、产品项不是对象……都会弹出**友好的错误说明**，页面不会崩溃
- **字段级清洗**：非法价格/重量归为空、未知枚举值归为「不明确」、字符串数字自动转换、负数拒绝
- 兼容直接导入一个裸的产品数组

## 九、安全性

- **不使用 `eval`**
- **不使用 `innerHTML` 拼接**：所有节点通过 `document.createElement` 创建，所有文本一律走 `textContent`。即使产品名里写了 `<img src=x onerror=alert(1)>`，也只会原样显示为文字，不会执行
- 导入 JSON 严格校验并重建对象，不直接把外部数据挂到内部状态上
- 数据完全保存在本地，不发起任何网络请求

## 十、体验细节

- 数字输入框禁止负数（`min="0"` + 输入时剥离 `-`）
- 价格允许留空；重量允许小数（如 `5.9`）；折叠尺寸独立填写长/宽/高
- 删除产品需确认；**清空全部需二次确认**；导入覆盖前必须选择方式
- 全部按钮有 hover / active / focus-visible 状态，表单有 focus 高亮
- 移动端按钮点击区域 ≥ 44px
- `label` 全部通过 `for` 正确关联 `input`
- **不使用 `alert()`**，统一用 Toast 与 Modal；Modal 支持 Esc 关闭、点击遮罩关闭、Tab 焦点循环
- 支持 `prefers-reduced-motion`，也做了打印样式
